🗑️5.1 실수로 커밋한 파일 제거하기

📍 상황: 비밀번호가 적힌 config.txt 파일을 실수로 커밋했습니다. 이미 GitHub에 올렸으니 어떻게 해야 할까요?

해결책 1: 파일만 히스토리에서 제거

파일 자체는 삭제하지 않고 Git 히스토리에서만 제거합니다:

# 파일을 스테이징에서 제거
git rm --cached config.txt

# .gitignore에 추가
echo "config.txt" >> .gitignore

# 커밋
git add .gitignore
git commit -m "Remove config.txt from tracking"

# Push
git push

해결책 2: 전체 히스토리에서 파일 제거 (고급)

모든 커밋 히스토리에서 파일을 제거하려면:

git filter-branch --tree-filter 'rm -f config.txt' HEAD
💡 팁: 이 명령어는 강력하지만 복잡합니다.
팀원이 이미 pull했다면 나중에 충돌이 생길 수 있습니다.

예방책

처음부터 이런 일을 방지하려면 .gitignore을 잘 설정하세요:

# .gitignore 파일
config.txt
*.key
.env
password.txt
✅ 해결! 비밀번호 파일은 더 이상 Git에 추적되지 않습니다. 하지만 한 번 공개된 정보이므로 비밀번호를 반드시 변경하세요!

⏮️5.2 이전 버전으로 완전히 되돌리기

📍 상황: 지난주의 커밋이 좋았는데, 지금까지의 모든 변경사항을 취소하고 싶습니다.

Step 1: 커밋 로그 확인

git log --oneline

Step 2: 원하는 커밋 확인

git show abc1234

Step 3: 그 커밋 상태로 되돌리기

옵션 A: 부드럽게 (새 커밋 생성)

git revert abc1234..HEAD

이렇게 하면 변경사항 되돌리는 새로운 커밋들이 생성됩니다.

옵션 B: 강하게 (히스토리 초기화)

git reset --hard abc1234

⚠️ 주의: abc1234 이후의 모든 변경사항이 완전히 삭제됩니다!

이미 Push한 경우

옵션 B를 사용했다면 force push해야 합니다:

git push origin master --force
⚠️ Force Push 주의!
팀 프로젝트에서는 반드시 팀원에게 알리고 force push하세요. 다른 사람의 작업을 덮어쓸 수 있습니다!
✅ 해결! 프로젝트가 이전 상태로 되돌려졌습니다.

🔀5.3 특정 파일만 다른 브랜치에서 가져오기

📍 상황: feature/profile 브랜치의 수정된 파일들 중 몇 개만 내 현재 브랜치에 적용하고 싶습니다.

방법 1: 특정 파일을 다른 브랜치에서 가져오기

git checkout feature/profile -- profile.html profile.css

방법 2: 특정 커밋의 변경사항만 가져오기

git cherry-pick abc1234

방법 3: 부분 병합 (병합의 일부만)

# 먼저 다른 브랜치의 변경사항을 확인
git diff feature/profile -- profile.html

# 파일을 수동으로 편집한 후
git add profile.html
git commit -m "Merge profile.html from feature/profile"
✅ 해결! 원하는 파일들만 가져왔습니다.

🔄5.4 협업할 때 최신 코드 유지하기

📍 상황: 팀원들이 계속 코드를 push하는데, 내 feature 브랜치는 마스터와 점점 멀어지고 있습니다. 나중에 병합할 때 충돌이 많을 것 같아요.

방법 1: Pull로 항상 최신 유지

매일 마스터의 최신 코드를 pull합니다:

git checkout master
git pull origin master
git checkout feature/myfeature
git merge master

방법 2: Rebase로 깔끔하게

마스터의 최신 커밋을 기반으로 다시 정렬합니다:

git fetch origin
git rebase origin/master

방법 3: 정기적인 병합

일주일에 한 번씩 master를 병합합니다:

git merge origin/master
# 충돌이 있으면 해결
git add .
git commit -m "Merge latest master"
git push origin feature/myfeature
✅ 해결! 최신 코드와 동기화되었고, 나중에 병합할 때 충돌이 적을 것입니다.

팀 협업 Best Practices

  • 매일 시작 전: git pull origin master
  • 작은 단위로: 자주 commit하기 (하루에 5~10번)
  • 자주 push하기: 로컬에만 두면 나중에 충돌 위험
  • 코드 리뷰: Pull Request로 병합하기
  • 충돌 빨리 해결: 충돌이 커지기 전에 해결

⚡빠른 참조 - 자주 사용하는 명령어

기본 작업

git status # 상태 확인
git add . # 모든 파일 추가
git commit -m "msg" # 커밋
git push # 원격에 올리기
git pull # 원격에서 가져오기

브랜치 작업

git branch # 브랜치 목록
git checkout -b name # 새 브랜치 생성
git checkout name # 브랜치 전환
git merge name # 병합
git branch -d name # 브랜치 삭제

히스토리 확인

git log --oneline # 커밋 로그
git diff # 변경사항
git show abc1234 # 특정 커밋 확인
git blame file.txt # 누가 수정했는지

문제 해결

git revert abc1234 # 커밋 되돌리기
git reset --hard HEAD~1 # 마지막 커밋 삭제
git stash # 변경사항 임시 저장
git cherry-pick abc1234 # 특정 커밋 적용

🎓Git 사용 시 핵심 팁

1️⃣ 자주 commit하기
큰 단위가 아니라 작은 단위로 자주 커밋하세요. 나중에 문제가 생기면 더 쉽게 찾을 수 있습니다.
2️⃣ 명확한 커밋 메시지
"update", "fix" 대신 "Add login validation" 처럼 구체적으로 작성하세요.
3️⃣ 매일 pull로 시작
작업을 시작하기 전에 항상 최신 코드를 받으세요.
4️⃣ 브랜치 활용하기
master는 항상 안정적으로 유지하고, feature 브랜치에서 개발하세요.
5️⃣ 위험한 명령어는 신중하게
--force, --hard 같은 옵션은 매우 조심해서 사용하세요.
