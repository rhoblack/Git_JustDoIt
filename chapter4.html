4장: 실수 바로잡기

누구나 실수합니다. Git은 실수를 되돌리는 강력한 도구를 제공합니다!

🎯 이 장을 마치면 다음을 할 수 있습니다:

  • git revert로 안전하게 커밋을 되돌릴 수 있다
  • git reset으로 로컬 커밋을 취소할 수 있다
  • git stash로 작업 중인 내용을 임시 저장할 수 있다
  • git rebase로 커밋 기록을 정리할 수 있다
  • git reflog로 실수를 복구할 수 있다
← 이전 장 다음 장 →

💡왜 배우나요?

코딩을 하다 보면 이런 상황이 생깁니다:

  • "방금 커밋한 것을 취소하고 싶어요"
  • "급한 버그 수정을 해야 하는데, 작업 중인 코드를 잠시 치워놓고 싶어요"
  • "커밋 메시지를 잘못 썼어요"
  • "아까 삭제한 코드가 필요해요"

Git은 이 모든 상황에 대한 해결책을 가지고 있습니다.

안심하세요

처음에는 revert만 기억하면 됩니다. 이 장에서 여러 도구를 배우지만, 가장 안전하고 간단한 것부터 시작합니다. 나머지는 필요할 때 다시 찾아보면 됩니다.

📌 난이도 안내
이 장의 도구들을 난이도 순으로 배웁니다:
쉬움 revert, stash
중간 reset, amend
심화 rebase, cherry-pick

↩️4.1 안전하게 되돌리기 (git revert) 쉬움

📌 용어: git revert

한글 정의: 특정 커밋의 변경사항을 취소하는 새로운 커밋을 만듭니다.

일상 비유: 이미 보낸 이메일을 "취소 메일"로 정정하는 것과 같습니다. 원래 이메일(커밋)은 기록에 남지만, "이전 내용을 취소합니다"라는 새 이메일이 추가됩니다.

왜 필요한가? 이미 GitHub에 push한 커밋도 안전하게 되돌릴 수 있습니다. 기록이 모두 남으므로 팀 작업에서 가장 안전합니다.

직접 해보기

Step 1: 되돌릴 실습용 커밋 만들기
$ echo "This is a mistake!" > mistake.txt
$ git add mistake.txt
$ git commit -m "Add mistake file (oops!)"
Step 2: 커밋 해시값 확인
$ git log --oneline -3

📊 예상 결과:

e5f6a7b (HEAD -> master) Add mistake file (oops!)
d4e5f6a Resolve merge conflict in greeting.txt
c3d4e5f Add greeting from master
Step 3: revert로 되돌리기
$ git revert e5f6a7b

에디터가 열리면 기본 메시지를 그대로 두고 저장합니다. (vi 에디터에서는 :wq 입력 후 Enter)

📊 예상 결과:

[master f6a7b8c] Revert "Add mistake file (oops!)"
1 file changed, 1 deletion(-)
delete mode 100644 mistake.txt
Step 4: 확인하기
$ ls

mistake.txt가 사라졌습니다!

$ git log --oneline -3

📊 예상 결과:

f6a7b8c (HEAD -> master) Revert "Add mistake file (oops!)"
e5f6a7b Add mistake file (oops!)
d4e5f6a Resolve merge conflict in greeting.txt

원래 커밋도 기록에 남아있고, "되돌리기 커밋"이 추가되었습니다. 완벽한 기록!

✅ 성공!
revert로 안전하게 커밋을 되돌렸습니다! 이것이 가장 안전한 방법입니다.

📦4.2 임시 저장하기 (git stash) 쉬움

📌 용어: git stash

한글 정의: 작업 중인 변경사항을 임시로 보관하고, 나중에 다시 꺼내 쓸 수 있는 기능입니다.

일상 비유: 책상 위에서 작업하다가 급한 일이 생겼을 때, 서류를 서랍에 잠시 넣어두는 것과 같습니다. 급한 일을 처리한 후 서랍에서 다시 꺼내면 됩니다.

왜 필요한가? 브랜치를 전환해야 하는데 아직 커밋할 준비가 안 된 코드가 있을 때 유용합니다.

직접 해보기

Step 1: 작업 중인 상태 만들기
$ echo "Work in progress..." >> hello.txt
$ git status

📊 예상 결과: hello.txt가 "modified" 상태입니다.

Step 2: 임시 저장하기
$ git stash

📊 예상 결과:

Saved working directory and index state WIP on master: f6a7b8c Revert "Add mistake file"
$ git status

📊 예상 결과: nothing to commit, working tree clean - 깨끗해졌습니다!

Step 3: 다른 작업 수행 (예: 급한 버그 수정)
$ echo "Bug fixed!" > bugfix.txt
$ git add bugfix.txt
$ git commit -m "Fix urgent bug"
Step 4: 임시 저장한 작업 복구하기
$ git stash pop

📊 예상 결과:

On branch master
Changes not staged for commit:
modified: hello.txt

Dropped refs/stash@{0}

hello.txt의 수정사항이 다시 돌아왔습니다!

✅ 성공!
작업을 잠시 치워두고 급한 일을 처리한 후 다시 복구했습니다!

stash 추가 명령어

$ git stash list # 저장된 stash 목록 보기
$ git stash apply # 복구하되 stash 유지
$ git stash drop # stash 삭제
$ git stash save "설명" # 설명 붙여서 저장
💡 stash vs commit의 차이
- stash: 임시 저장. 기록에 남지 않음. 잠깐 치워둘 때 사용.
- commit: 영구 저장. 기록에 남음. 작업 완료 후 사용.

⏪4.3 커밋 취소하기 (git reset) 중간

📌 용어: git reset

한글 정의: 커밋을 취소하고 이전 상태로 되돌립니다. revert와 달리 커밋 자체를 삭제합니다.

일상 비유: 일기를 쓰다가 마지막 페이지를 찢어버리는 것과 같습니다. 그 페이지가 있었다는 사실도 사라집니다.

왜 필요한가? 아직 push하지 않은 로컬 커밋을 깔끔하게 취소할 때 사용합니다.

안심하세요

reset은 아직 push하지 않은 로컬 커밋에만 사용하면 안전합니다. 이미 push한 커밋은 revert를 사용하세요.

만약 실수로 reset을 잘못 사용했더라도, git reflog(4.5절에서 배웁니다)로 복구할 수 있습니다!

reset의 세 가지 모드

옵션 커밋 스테이징 파일 비유
--soft 취소 유지 유지 택배 발송만 취소, 물건은 포장 대기 테이블에
--mixed (기본값) 취소 취소 유지 발송 취소 + 포장 풀기, 물건은 그대로
--hard 취소 취소 삭제 발송 취소 + 포장 풀기 + 물건도 버리기

직접 해보기

Step 1: 먼저 stash한 변경사항 커밋하기
$ git add hello.txt
$ git commit -m "Add work in progress (will reset this)"
Step 2: soft reset - 커밋만 취소
$ git reset --soft HEAD~1

HEAD~1은 "현재 위치에서 1개 전 커밋"을 의미합니다.

$ git status

📊 예상 결과: 파일은 스테이징된 상태로 남아있습니다. 커밋만 취소되었습니다.

Step 3: 다시 커밋한 후 mixed reset 시도
$ git commit -m "Add work in progress (will reset again)"
$ git reset HEAD~1

(--mixed가 기본값이므로 생략 가능합니다)

$ git status

📊 예상 결과: 파일 변경사항은 있지만 스테이징되지 않은 상태입니다.

Step 4: 정리 - 변경사항을 다시 커밋
$ git add hello.txt
$ git commit -m "Update hello.txt with progress"
✅ 성공!
reset으로 커밋을 취소하고 다시 만드는 방법을 배웠습니다!
⚠️ --hard 사용 시 주의
git reset --hard는 파일 변경사항까지 모두 삭제합니다.
로컬에서만 사용하세요. 이미 push한 커밋에는 사용하지 마세요.
실수해도 git reflog로 복구할 수 있습니다 (4.5절 참조).

커밋 메시지만 수정하기

마지막 커밋의 메시지만 바꾸고 싶다면:

$ git commit --amend -m "새로운 커밋 메시지"

아직 push하지 않은 마지막 커밋에만 사용하세요.

✂️4.4 커밋 기록 정리하기 (git rebase) 심화

📌 용어: git rebase

한글 정의: 커밋 기록을 재정렬하거나, 여러 커밋을 하나로 합칠 수 있는 기능입니다.

일상 비유: 일기장에서 3일치 일기를 한 페이지로 요약하거나, 날짜 순서를 바꾸는 것과 같습니다.

왜 필요한가? "typo 수정", "다시 수정", "진짜 수정" 같은 불필요한 커밋들을 하나로 합쳐서 깔끔한 기록을 만들 수 있습니다.

안심하세요

rebase는 아직 push하지 않은 로컬 커밋에만 사용하면 안전합니다. 이미 push한 커밋을 rebase하면 팀원과 충돌이 생길 수 있으므로, 로컬에서만 사용하세요.

이 기능이 어려우면 건너뛰어도 됩니다. 나중에 필요할 때 다시 찾아보세요!

직접 해보기: 커밋 합치기 (squash)

Step 1: 실습용 커밋 3개 만들기
$ echo "line 1" > rebase-test.txt
$ git add rebase-test.txt
$ git commit -m "Add rebase test file"

$ echo "line 2" >> rebase-test.txt
$ git add rebase-test.txt
$ git commit -m "Fix typo in rebase test"

$ echo "line 3" >> rebase-test.txt
$ git add rebase-test.txt
$ git commit -m "Final fix for rebase test"
Step 2: 최근 3개 커밋 확인
$ git log --oneline -3

📊 예상 결과:

h8i9j0k Final fix for rebase test
g7h8i9j Fix typo in rebase test
f6g7h8i Add rebase test file

이 3개 커밋을 하나로 합쳐보겠습니다.

Step 3: Interactive Rebase 시작
$ git rebase -i HEAD~3

에디터가 열리면 다음과 같이 보입니다:

pick f6g7h8i Add rebase test file
pick g7h8i9j Fix typo in rebase test
pick h8i9j0k Final fix for rebase test
Step 4: 합칠 커밋 표시하기

두 번째와 세 번째 줄의 pick을 squash(또는 줄여서 s)로 변경합니다:

pick f6g7h8i Add rebase test file
squash g7h8i9j Fix typo in rebase test
squash h8i9j0k Final fix for rebase test

저장하고 닫으면 (:wq), 새로운 커밋 메시지를 작성하는 에디터가 열립니다.

Step 5: 합쳐진 커밋 메시지 작성

기존 메시지를 모두 지우고 새 메시지를 작성합니다:

Add rebase test file with complete content

저장하고 닫으면 3개 커밋이 1개로 합쳐집니다!

Step 6: 결과 확인
$ git log --oneline -3

3개 커밋이 1개로 합쳐진 것을 확인할 수 있습니다!

✅ 성공!
3개 커밋을 1개로 깔끔하게 합쳤습니다!

Rebase 주요 옵션

명령어 의미
pick 커밋 유지 (변경 없이)
reword 커밋 메시지만 수정
squash 이전 커밋과 합치기 (메시지도 합침)
fixup 이전 커밋과 합치기 (메시지는 버림)
drop 커밋 삭제
💡 Rebase vs Merge
- Merge: 두 브랜치의 기록이 모두 남음. 안전하지만 기록이 복잡해질 수 있음.
- Rebase: 기록을 정리하여 깔끔하게 만듦. 로컬에서만 사용해야 안전.
팀 정책에 따라 선택하세요. 처음에는 merge를 사용하는 것이 안전합니다.

🔄4.5 최후의 보험: git reflog 중간

📌 용어: git reflog

한글 정의: Git에서 일어난 모든 작업의 기록을 보여줍니다. reset이나 rebase로 사라진 커밋도 여기서 찾을 수 있습니다.

일상 비유: 엑셀의 "실행 취소(Ctrl+Z) 기록"과 같습니다. 여러분이 한 모든 작업이 시간순으로 기록되어 있어서, 아무리 심하게 꼬여도 이전 상태로 되돌릴 수 있습니다.

왜 필요한가? git reset --hard로 커밋을 삭제했어도, reflog에는 기록이 남아있어 복구할 수 있습니다!

reflog는 여러분의 안전망입니다

Git에서 무언가를 잘못했다고 느껴질 때, 당황하지 마세요. reflog에 모든 기록이 있습니다. 약 90일간 보관됩니다.

직접 해보기: reflog로 복구하기

Step 1: 실수 시뮬레이션 - 중요한 파일을 커밋한 후 reset으로 삭제
$ echo "Very important data!" > important.txt
$ git add important.txt
$ git commit -m "Add important data"
$ git reset --hard HEAD~1

이제 important.txt가 사라졌습니다! 커밋도 사라진 것 같습니다.

Step 2: reflog에서 삭제된 커밋 찾기
$ git reflog

📊 예상 결과:

a1b2c3d (HEAD -> master) HEAD@{0}: reset: moving to HEAD~1
x9y8z7w HEAD@{1}: commit: Add important data
a1b2c3d HEAD@{2}: rebase (finish): ...
...

"Add important data" 커밋이 여전히 기록에 있습니다! 해시값 x9y8z7w를 기억하세요.

Step 3: 삭제된 커밋 복구하기
$ git reset --hard x9y8z7w

(실제로는 reflog에서 본 해시값을 사용하세요)

Step 4: 복구 확인
$ ls

important.txt가 돌아왔습니다!

$ cat important.txt

📊 예상 결과: Very important data!

✅ 성공!
삭제된 커밋을 reflog로 복구했습니다! reflog는 여러분의 안전망입니다.

🍒4.6 특정 커밋만 가져오기 (cherry-pick) 심화

📌 용어: git cherry-pick

한글 정의: 다른 브랜치의 특정 커밋 하나만 현재 브랜치에 적용합니다.

일상 비유: 과일 바구니에서 체리만 골라 따는 것처럼, 여러 커밋 중 원하는 것만 골라서 가져옵니다.

직접 해보기

Step 1: 다른 브랜치의 커밋 해시 찾기
$ git log --oneline other-branch
Step 2: 현재 브랜치에 적용
$ git cherry-pick abc1234

해당 커밋의 변경사항이 현재 브랜치에 새로운 커밋으로 적용됩니다.

💡 사용 상황
- 버그 수정 커밋을 다른 브랜치에도 적용할 때
- 실수로 잘못된 브랜치에 커밋한 것을 옮길 때

📚4장 핵심 요약

상황 명령어 난이도 안전성
push한 커밋 되돌리기 git revert 쉬움 매우 안전
작업 임시 저장 git stash 쉬움 안전
로컬 커밋 취소 git reset 중간 로컬만 안전
커밋 메시지 수정 git commit --amend 중간 로컬만 안전
실수 복구 git reflog 중간 안전 (읽기 전용)
커밋 기록 정리 git rebase -i 심화 로컬만 안전
특정 커밋만 적용 git cherry-pick 심화 안전
📌 기억할 것 하나만!
어떤 도구를 써야 할지 모르겠다면, revert를 사용하세요. 가장 안전하고, 대부분의 상황에서 충분합니다.
