↩️4.1 실수한 커밋 되돌리기

잘못된 커밋을 했을 때 이를 취소하는 방법은 여러 가지입니다. 상황에 따라 다릅니다.

git revert - 안전한 되돌리기

이미 공개된 커밋을 되돌릴 때 사용합니다. 새로운 커밋을 만들어서 변경을 되돌립니다.

Step 1: 커밋 로그 확인
git log --oneline
Step 2: 특정 커밋 되돌리기
git revert abc1234

"abc1234"는 커밋의 해시값입니다. 해당 커밋의 변경을 취소하는 새로운 커밋이 만들어집니다.

✅ revert의 특징
- 이력이 남으므로 협업에 안전
- 이미 push한 커밋을 되돌릴 때 사용
- 새로운 커밋이 생성됨

git reset - 강력한 되돌리기

아직 push하지 않은 로컬 커밋을 완전히 삭제합니다.

Step 1: 이전 커밋으로 돌아가기
git reset --soft HEAD~1

마지막 커밋을 취소하지만 파일 변경사항은 유지합니다.

reset의 세 가지 옵션

옵션 효과 파일 변경사항
--soft 커밋만 취소 유지 (staged)
--mixed (기본값) 커밋 + staging 취소 유지 (unstaged)
--hard 커밋 + 파일 변경사항 모두 삭제 완전히 삭제
⚠️ --hard 주의!
git reset --hard는 변경사항을 완전히 삭제합니다. 신중하게 사용하세요!

언제 어떤 것을 사용할까?

  • 이미 push한 커밋: git revert
  • 로컬에만 있는 커밋: git reset
  • 마지막 커밋 메시지 수정: git commit --amend

📦4.2 변경사항 임시 저장하기 (Stash)

작업 중인 변경사항을 임시로 저장하고 나중에 다시 불러올 수 있습니다.

사용 상황

  • 브랜치를 전환해야 하는데 커밋할 준비가 안 됨
  • 다른 일을 먼저 해야 할 때 현재 작업을 보관
  • 실험적인 변경사항을 나중에 적용

따라하기

Step 1: 현재 변경사항 stash
git stash

또는 설명을 붙여서:

git stash save "작업 설명"
Step 2: 다른 브랜치로 전환
git checkout other-branch

작업 디렉토리가 깨끗해집니다!

Step 3: 원래 브랜치로 돌아와서 복구
git stash pop

저장된 변경사항이 다시 나타납니다!

stash 목록 보기

git stash list

특정 stash 복구

git stash apply stash@{0}
💡 stash vs commit
- stash: 임시 저장 (나중에 적용)
- commit: 영구 저장 (히스토리 남음)
완성되지 않은 작업은 stash, 완성된 작업은 commit!

✂️4.3 커밋 히스토리 정리하기 (Rebase)

Rebase는 여러 작은 커밋들을 하나로 만들거나, 커밋 순서를 정렬할 때 사용합니다. (고급 기능)

Interactive Rebase 사용

최근 3개의 커밋을 정리하려면:

git rebase -i HEAD~3

텍스트 에디터가 열려서 다음과 같은 옵션을 보여줍니다:

pick abc1234 First commit
pick def5678 Second commit
pick ghi9012 Third commit

Rebase 옵션

명령어 의미
pick 커밋 유지
reword 커밋 메시지 수정
squash 이전 커밋과 합치기
drop 커밋 삭제
⚠️ Rebase 주의!
이미 push한 커밋을 rebase하면 히스토리가 충돌될 수 있습니다. 로컬 커밋만 rebase하세요!
💡 Rebase vs Merge
- Merge: 커밋 이력 전체 유지
- Rebase: 깔끔한 히스토리
팀 정책에 따라 사용하세요!

🎯4.4 특정 커밋만 적용하기 (Cherry-pick)

다른 브랜치의 특정 커밋만 현재 브랜치에 적용할 때 사용합니다.

사용 상황

  • 버그 수정 커밋을 다른 브랜치에도 적용
  • 실수로 잘못된 브랜치에 커밋한 것 옮기기

따라하기

Step 1: 복사할 커밋의 해시 찾기
git log --oneline other-branch
Step 2: 현재 브랜치에 적용
git cherry-pick abc1234

해당 커밋의 변경사항이 현재 브랜치에 적용됩니다!

💡 여러 커밋 한 번에
git cherry-pick abc1234..def5678
abc1234부터 def5678까지 모든 커밋을 적용합니다.

상황 사용 명령어 설명
공개된 커밋 취소 git revert 새로운 커밋으로 되돌리기
로컬 커밋 취소 git reset 커밋 완전히 삭제
임시 저장 git stash 나중에 복구 가능
히스토리 정리 git rebase 커밋 순서 정렬
특정 커밋만 git cherry-pick 원하는 커밋만 적용
