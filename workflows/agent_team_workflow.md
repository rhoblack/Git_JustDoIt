# 에이전트 팀 워크플로우

## Phase 구조 (4 Phase)

```
Phase 1: 기획 회의 (3명 병렬)
    ↓ (리뷰어 선택, 기술 저자 준비)
Phase 2: 초안 작성 (기술 저자 단독)
    ↓ (원고 작성)
Phase 3: 병렬 리뷰 (4명 동시)
    ↓ (review_logs 생성)
Phase 4: 종합 회의 및 수정
    ↓ (최종 승인)
완료
```

---

## Phase 1: 기획 회의 (3명 병렬)

**참여자**: 교육 설계자, 교육심리전문가, 교육전문강사
**시간**: 30분
**산출물**: chapter_plan.md

### 실행 순서

1. **팀 생성** (Team Lead)
```bash
TeamCreate {
  team_name: "git-textbook-ch1"
  description: "Chapter 1 시작하기 집필 및 리뷰"
  agent_type: "editor-in-chief"
}
```

2. **3명 에이전트 스폰**
```
Teammate 1: 📐 교육 설계자
Teammate 2: 🧠 교육심리전문가
Teammate 3: 🎤 교육전문강사
```

3. **기획 회의 프롬프트**
```markdown
# Chapter N 기획 회의

## 요청
- 학습 목표 검토
- 예상 학습 시간 검토
- 실습 내용 검토
- 심리적 안전성 고려사항 정리
- 강의 흐름 제안

각각 15분 내에 의견을 정리해주세요.
```

### 산출물 형식

**파일**: workflows/chapter1_plan.md

```markdown
# Chapter 1 - 기획 회의 결과

## 학습 목표 (교육 설계자)
- 확인됨 ✅
- 수정 권장: ...

## 실습 설계 (교육 설계자)
- [실습 1] 적절함 ✅
- [실습 2] 난이도 조정 필요 ...

## 심리적 고려사항 (심리전문가)
- 불안 지점: ...
- 대응 방법: ...

## 강의 포인트 (교육전문강사)
- 강조할 부분: ...
- FAQ 예상: ...

## 최종 의견
준비 완료 ✅
```

## Phase 2: 초안 작성 (기술 저자 단독)

**참여자**: 기술 저자
**시간**: 2시간
**산출물**: chapterN.html

### 실행 순서

1. **기술 저자 스폰**
```markdown
이전 Phase 1에서 받은 기획안을 바탕으로
chapterN.html을 작성해주세요.

요구사항:
- TABLE_OF_CONTENTS.md의 구조 따르기
- 각 섹션 2000~4000자
- SVG 다이어그램 포함
- 따라하기 실습 포함
- 모든 Git 명령어 테스트 후 포함
```

2. **자체 점검**
- [ ] HTML 문법 검증
- [ ] 모든 링크 확인
- [ ] 명령어 실행 테스트
- [ ] 이전 장과의 연결 확인

3. **제출**
```
원고 완성 → 편집장에 제출 → Phase 3 진행
```

---

## Phase 3: 병렬 리뷰 (4명 동시)

**참여자**: 기술 리뷰어, 초보자 독자, 교육 설계자, 심리전문가
**시간**: 1시간 (각 25분)
**산출물**: 4개 리뷰 파일 (review_logs/)

### 실행 순서

1. **4명 리뷰어 동시 스폰**
```markdown
각각 자신의 관점에서 chapter1.html을 리뷰해주세요.

리뷰어별 역할:
- 🔍 기술 리뷰어: Git 명령어 정확성
- 🎓 초보자 독자: 이해도 평가
- 📐 교육 설계자: 학습 구조 평가
- 🧠 심리전문가: 안전성 평가

각자 agents/*.md의 체크리스트를 사용해주세요.
```

2. **독립 리뷰 진행**
- 각자 자신의 review_logs 파일 작성
- 다른 리뷰어의 의견을 보지 않음 (독립성)

3. **리뷰 완료**
```
4개 리뷰 파일:
- review_logs/chapter1_tech_review.md
- review_logs/chapter1_beginner_review.md
- review_logs/chapter1_edu_review.md
- review_logs/chapter1_psych_review.md
```

### 리뷰 항목 체크리스트

**기술 리뷰어**:
- [ ] 모든 git 명령어 정확성
- [ ] OS 호환성 (Windows, Mac, Linux)
- [ ] 모범 사례 준수
- [ ] 위험 경고 명시

**초보자 독자**:
- [ ] 이해도 5점 척도 평가
- [ ] 용어 설명 완성도
- [ ] 따라하기 가능성
- [ ] 실습 성공 가능성

**교육 설계자**:
- [ ] 학습 목표와 내용 일치
- [ ] 블룸 분류 5수준 포함
- [ ] 인지 부하 적절성
- [ ] 실습 난이도 증가

**심리전문가**:
- [ ] 동기 유지 장치
- [ ] 자기효능감 관리
- [ ] 불안 지점 감지
- [ ] 감정 곡선 자연스러움

## Phase 4: 종합 회의 및 수정

**참여자**: 편집장 (Team Lead) + 기술 저자
**시간**: 1시간 (30분 회의 + 30분 수정)
**산출물**: 수정된 chapterN.html + 최종 승인

### 실행 순서

1. **편집장이 4개 리뷰 통합**
```markdown
# Chapter 1 리뷰 통합

## Critical Issues (즉시 수정)
1. [섹션] - [문제] - [이유]
2. ...

## Major Issues (수정 권장)
1. ...

## Minor Issues (참고)
1. ...

## 우선순위
위의 우선순위 기준 적용
```

2. **기술 저자와 회의**
- 각 이슈에 대해 토론
- 수정 방향 결정
- 재검토 항목 명시

3. **수정 작업**
- 기술 저자가 즉시 수정
- 주요 부분은 편집장이 재확인

4. **최종 승인**
```
✅ 모든 Critical 이슈 해결
✅ 모든 Major 이슈 해결
✅ 이해도 ⭐⭐⭐ 이상
✅ 기술 정확성 확인
✅ 교육 설계 우수

→ 최종 승인!
```
