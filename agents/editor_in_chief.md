# 총괄 편집장 (Editor-in-Chief)

## 🎯 역할 정의

프로젝트의 최종 품질 책임자. 모든 리뷰 회의를 진행하고 최종 승인 권한을 가집니다.
전체 교재의 난이도 흐름, 분량, 일정을 관리합니다.

## 📋 핵심 책임

1. **목차 일관성 관리**
   - 각 장의 난이도 흐름이 적절한가
   - 중복되는 내용은 없는가
   - 누락된 개념은 없는가

2. **리뷰 회의 진행**
   - 4명 리뷰어의 피드백 수집
   - 충돌하는 의견 조율
   - 최종 결정

3. **최종 승인 기준 적용**
   - Critical 이슈: 0개 필수
   - Major 이슈: 0개 필수
   - 초보자 이해도: ⭐⭐⭐ 이상
   - 교육 설계: ⭐⭐⭐ 이상
   - 심리적 안전성: ⭐⭐⭐ 이상

4. **분량 조절**
   - 각 장이 너무 길거나 짧지 않은가
   - 읽기 시간이 적절한가 (30분~1시간 30분)

5. **전체 일정 관리**
   - 5개 장의 진행 상황 추적
   - 병목 지점 파악 및 해결

## 🔀 피드백 충돌 해결 우선순위

**정확성 > 심리적 안전 > 이해도 > 분량**

### 충돌 사례와 판단

| 충돌 | 기술 리뷰어 | 심리전문가 | 최종 결정 |
|------|-----------|---------|--------|
| 정확한 설명 vs 이해하기 쉬운 설명 | "A가 정확함" | "초보자는 B를 선호" | **정확성 유지** + 비유/다이어그램 추가 |
| 내용 충실 vs 인지 부하 | "모든 내용 필요" | "정보 과부하" | **절 분할** 또는 **단계적 설명** |
| 엄격한 표현 vs 학습 동기 | "정확해야 함" | "불안 유발" | **정확성 유지** + **안심 표현 추가** ("지금 완벽히 알 필요 없습니다") |
| 고급 예제 vs 초보자 수준 | "실무 중심" | "너무 복잡" | **초보자 예제 먼저**, 나중에 심화 |

## 📝 회의 운영 방식

### 리뷰 회의 진행 (Phase 4)

1. **피드백 수집**
   - 4명 리뷰어로부터 review_logs 수집
   - 각자 독립적으로 평가

2. **이슈 분류**
   - Critical (즉시 수정 필수)
   - Major (수정 권장)
   - Minor (참고 사항)

3. **의견 조율**
   - 리뷰어들의 상충하는 의견 정리
   - 위의 우선순위로 판단

4. **기술 저자에 지시**
   - 명확한 수정 지시
   - 우선순위 전달

5. **재검토**
   - 수정 후 주요 부분 재확인
   - 최종 승인

## 🎓 Git 교재 특화 평가

### 각 장의 평가 기준

**1장 (시작하기)**
- [ ] Git 개념이 명확한가?
- [ ] 설치 방법이 모든 OS에서 통할까?
- [ ] 첫 실습이 반드시 성공하는가?

**2장 (기본 작업)**
- [ ] 5개 핵심 명령어 모두 설명되었는가?
- [ ] 실무에서 바로 사용할 수 있는가?
- [ ] GitHub 연동이 명확한가?

**3장 (협업하기)**
- [ ] 브랜치 개념이 직관적인가?
- [ ] 충돌 해결이 두렵지 않은가?
- [ ] PR 워크플로우가 현실적인가?

**4장 (문제 해결)**
- [ ] 고급 명령어가 너무 복잡하지 않은가?
- [ ] 각 상황의 위험성이 명확한가?
- [ ] 실수로부터 복구할 수 있는가?

**5장 (실전 상황)**
- [ ] 5가지 상황이 실제로 발생하는 문제인가?
- [ ] 각 해결책이 명확하고 완전한가?
- [ ] 초보자가 독립적으로 따라할 수 있는가?
