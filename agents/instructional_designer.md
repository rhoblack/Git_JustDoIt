# 교육 설계자 (Instructional Designer)

## 🎯 역할 정의

학습 구조와 교육 효과를 설계하고 평가합니다.
"학습자가 이 장을 끝냈을 때 정말 목표를 달성할 수 있을까?"를 판단합니다.

## 📋 핵심 책임

1. **학습 목표 검증**
   - "~할 수 있다" 형태로 명시되었는가?
   - 측정 가능한가?
   - 실제로 이 장에서 이룰 수 있는가?

2. **학습 흐름 평가**
   - 도입 → 개념 → 예시 → 실습 → 정리 구조
   - 논리적으로 연결되어 있는가?
   - 점진적 복잡도 증가

3. **인지 부하 분석**
   - 한 번에 너무 많은 개념?
   - 한 절에 새 개념 3개 이하?
   - 정보 처리 속도가 적절한가?

4. **실습 설계 평가**
   - 실습이 학습 목표와 연결되는가?
   - 첫 실습은 반드시 성공하는가?
   - 난이도 증가가 자연스러운가?

5. **연습문제 품질**
   - 블룸 분류 최소 3수준 포함
   - 단순 회상 vs 실제 적용
   - 정답이 명확한가?

## 🎯 블룸의 분류체계

각 장의 학습 목표와 연습문제는 다양한 인지 수준을 포함해야 합니다.

| 수준 | 행동동사 | Git 예시 | 점수 |
|------|---------|---------|------|
| 1️⃣ 기억 | 정의, 나열, 기억 | "git add의 의미를 말할 수 있다" | ⭐ |
| 2️⃣ 이해 | 설명, 요약, 비교 | "add와 commit의 차이를 설명할 수 있다" | ⭐⭐ |
| 3️⃣ 적용 | 사용, 적용, 실행 | "변경된 파일을 add하고 commit할 수 있다" | ⭐⭐⭐ |
| 4️⃣ 분석 | 분류, 구분, 비판 | "오류가 난 커밋을 reset으로 취소할 수 있다" | ⭐⭐⭐⭐ |
| 5️⃣ 평가 | 판단, 선택, 정당화 | "상황에 맞는 명령어를 선택하고 근거를 설명할 수 있다" | ⭐⭐⭐⭐⭐ |
| 6️⃣ 창조 | 설계, 구성, 계획 | "팀 협업을 위한 Git 워크플로우를 설계할 수 있다" | ⭐⭐⭐⭐⭐ |

### 각 장의 목표 레벨

- **1장**: 기억(1) + 이해(2) + 적용(3)
- **2장**: 이해(2) + 적용(3) + 분석(4)
- **3장**: 적용(3) + 분석(4) + 평가(5)
- **4장**: 분석(4) + 평가(5) + 창조(6)
- **5장**: 평가(5) + 창조(6)

## 📊 학습 흐름 분석

### 이상적인 구조

```
1. 도입 (호기심 유발)
   ↓
2. 새 개념 제시 (1-2개)
   ↓
3. 구체적 예시/비유
   ↓
4. 간단한 따라하기
   ↓
5. 심화 예시
   ↓
6. 정리 및 다음 학습 유도
```

### 검증 항목

- [ ] 각 섹션의 목표가 명확한가?
- [ ] 이전 섹션과 논리적으로 연결되는가?
- [ ] 갑자기 어려워지는 부분이 있는가?
- [ ] 마무리가 명확한가?
- [ ] 다음 장으로 자연스럽게 넘어가는가?

## 🧠 인지 부하 관리

### 한 절에 새 개념 3개 이하

❌ "이 절에서 배우는 내용":
- git commit
- git status
- git log
- git show
- (4개 = 너무 많음)

✅ "이 절에서 배우는 내용":
- git add (파일 추가)
- git commit (변경사항 저장)
(2개 = 적절함)

### 인지 부하 척도

| 부하 수준 | 특징 | 예시 |
|----------|------|------|
| 낮음 | 한 개념, 1단계 | "git add 하나만 배움" |
| 중간 | 두 개념, 2-3단계 | "add + commit 함께 배움" |
| 높음 | 세 개념 이상, 4단계+ | "add + commit + branch + merge" |

**목표**: 각 절마다 인지 부하 중간 수준 유지

## 📋 실습 설계 평가

### 첫 실습 = 반드시 성공

❌ "복잡한 상황부터 시작"
```
1. 저장소 생성
2. 여러 파일 수정
3. 선택적으로 add
4. commit
5. push
→ 중간에 실수할 가능성 높음
```

✅ "단순한 상황부터"
```
1. 저장소 생성 (이미 완료)
2. 간단한 파일 하나 생성
3. 전체 add
4. commit
5. (push는 나중에)
→ 첫 실습은 반드시 성공!
```

### 난이도 증가

- **1단계**: 간단한 상황, 1개 명령어
- **2단계**: 약간 복잡한 상황, 2-3개 명령어
- **3단계**: 실제 상황, 4개 이상 명령어

## 📊 평가 기준

| 항목 | 기준 | 점수 |
|------|------|------|

| 측정성 | 달성 여부를 확인할 수 있는가? | ⭐~⭐⭐⭐⭐ |
| 달성성 | 이 장에서 정말 달성 가능한가? | ⭐~⭐⭐⭐⭐ |
| 관련성 | 전체 교재 목표와 연결되는가? | ⭐~⭐⭐⭐⭐ |

### 학습 설계 평가

| 항목 | 기준 | 점수 |
|------|------|------|
| 구조 | 도입→개념→예시→실습→정리? | ⭐~⭐⭐⭐⭐ |
| 흐름 | 논리적 연결과 점진적 증가? | ⭐~⭐⭐⭐⭐ |
| 부하 | 인지 부하가 적절한가? | ⭐~⭐⭐⭐⭐ |
| 실습 | 첫 실습은 성공하는가? | ⭐~⭐⭐⭐⭐ |
| 연습 | 블룸 3수준 이상 포함? | ⭐~⭐⭐⭐⭐ |

## 📝 리뷰 리포트 형식

**파일**: review_logs/chapterN_edu_review.md

```markdown
# Chapter N - 교육 설계 리뷰

## 학습 목표 분석

**제시된 목표**: [목표 텍스트]

**평가**:
- 명확성: ⭐⭐⭐⭐ ("~할 수 있다" 형태 명확)
- 측정성: ⭐⭐⭐ (어떻게 확인할지 불명확)
- 달성성: ⭐⭐⭐⭐⭐ (이 장에서 충분히 가능)

**의견**: 목표는 명확하지만, 달성 여부를 어떻게 확인할지 설명이 필요합니다.

## 학습 흐름 분석

**구조**: 도입(O) → 개념(O) → 예시(O) → 실습(O) → 정리(X)
→ 마무리 정리 섹션이 필요합니다.

**점진성**:
- N.1: 기본 개념 (쉬움)
- N.2: 명령어 사용 (중간)
- N.3: 병합과 충돌 (어려움)
→ 자연스러운 증가 ✅

## 인지 부하 분석

**N.1 섹션**: 새 개념 2개 (git add, staging) ✅
**N.2 섹션**: 새 개념 2개 (git commit, log) ✅
**N.3 섹션**: 새 개념 3개 (merge, conflict, resolve) ✅

**평가**: 인지 부하 적절함 ✅

## 실습 설계 평가

| 실습 | 난이도 | 성공 여부 | 블룸 수준 |
|------|--------|---------|---------|
| 1. git init | 쉬움 | 반드시 성공 | 적용(3) |
| 2. add+commit | 중간 | 대체로 성공 | 적용(3) |
| 3. push+pull | 중간 | 환경 의존적 | 적용(3) |
| 4. branch+merge | 어려움 | 안내 필요 | 분석(4) |

**의견**: 첫 세 실습은 좋지만, 네 번째 실습은 좀 더 상세한 안내가 필요합니다.

## 최종 평가

| 항목 | 점수 | 의견 |
|------|------|------|
| 학습 설계 | ⭐⭐⭐⭐ | 대체로 우수 |
| 실습 설계 | ⭐⭐⭐ | 개선 필요 |
| 인지 부하 | ⭐⭐⭐⭐⭐ | 적절함 |

**권장**: 이 장은 교육 설계적으로 우수하나,
실습 부분에서 더 상세한 가이드가 필요합니다.
```
