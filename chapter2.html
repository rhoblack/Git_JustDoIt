📝2.1 파일 추가하기 (git add)

이제 실제로 파일을 만들고 Git에 추가해봅시다. 파일을 Git에 추가하는 것은 "이 파일의 변경사항을 기록해주세요"라고 말하는 것입니다.

따라하기

Step 1: 텍스트 파일 만들기

텍스트 에디터(메모장 등)로 파일을 만듭니다:

echo "Hello, Git!" > hello.txt
Step 2: 저장소 상태 확인
git status

출력 예시:

Untracked files:
hello.txt

"Untracked"는 "Git이 추적하지 않고 있는" 파일이라는 뜻입니다.

Step 3: 파일을 Git에 추가
git add hello.txt

이 명령어는 파일을 "스테이징 영역(Staging Area)"에 추가합니다.

Step 4: 다시 상태 확인
git status

이제 "Changes to be committed:" 아래에 파일이 나타납니다!

여러 파일 한 번에 추가

모든 파일을 추가하려면:

git add .

또는 특정 폴더의 모든 파일:

git add folder-name/
파일의 상태 변화

파일 생성 → Untracked 상태
↓ (git add)
Staged 상태 (준비 완료)
↓ (git commit)
Committed 상태 (기록됨)

💾2.2 변경사항 저장하기 (git commit)

스테이징된 파일들을 실제로 Git 저장소에 저장하는 것을 "커밋(commit)"이라고 합니다. 각 커밋은 하나의 버전을 만드는 것입니다.

따라하기

Step 1: 커밋 메시지와 함께 저장
git commit -m "Add hello.txt file"

"-m" 옵션은 "메시지"를 의미하고, 큰따옴표 안에 변경사항을 설명합니다.

💡 좋은 커밋 메시지 작성 팁
✅ 좋은 예: "Add login feature", "Fix bug in calculation"
❌ 나쁜 예: "asdf", "fixed", "update"
명확하고 간결하게 무엇을 했는지 설명하세요!
Step 2: 상태 확인
git status

이제 "nothing to commit, working tree clean"이라는 메시지가 나타납니다!

커밋 로그 보기

지금까지 만든 커밋들을 보려면:

git log

더 간단하게 보려면:

git log --oneline
📌 커밋의 의미
커밋은 타임캡슐처럼, 그 시점에서의 프로젝트 모든 파일의 상태를 기록합니다. 언제든지 이전 커밋 상태로 되돌릴 수 있습니다!

🔍2.3 저장소 상태 확인하기

Git 작업을 하다 보면 현재 상태를 파악해야 합니다. 그럴 때 사용하는 명령어들입니다.

git status - 현재 상태 확인

git status

이 명령어로 알 수 있는 것:

  • 현재 브랜치 이름
  • 변경되었지만 커밋되지 않은 파일들
  • 스테이징된(커밋 준비 완료) 파일들

git log - 커밋 히스토리 보기

git log

한 줄씩 간단하게 보기:

git log --oneline

최근 5개 커밋만 보기:

git log --oneline -5

git diff - 변경사항 보기

파일이 어떻게 변경되었는지 보려면:

git diff

커밋된 변경사항만 보기:

git diff --staged

따라해보기

Step 1: 파일 수정
echo "Hello, Git World!" > hello.txt
Step 2: 변경사항 확인
git status

"modified: hello.txt"가 나타났나요?

Step 3: 정확히 뭐가 바뀌었는지 보기
git diff

"-" 로 시작하는 줄은 제거된 부분, "+"로 시작하는 줄은 추가된 부분입니다.

🔄2.4 원격 저장소와 동기화하기

GitHub, GitLab 같은 원격 서버에 코드를 올리고 가져오는 방법을 배워봅시다.

원격 저장소 추가하기

먼저 GitHub에서 저장소를 만든 후, 다음 명령어로 연결합니다:

git remote add origin https://github.com/당신의username/저장소이름.git

잘 연결됐는지 확인:

git remote -v

Push - 로컬에서 원격으로 올리기

로컬 저장소의 커밋을 GitHub에 올립니다:

git push origin master

이후부터는 더 간단하게:

git push

Pull - 원격에서 로컬로 가져오기

다른 사람의 변경사항이나 원격 저장소의 업데이트를 가져옵니다:

git pull origin master

또는 간단하게:

git pull
Git 기본 워크플로우

1. 파일 수정
2. git add (스테이징)
3. git commit (로컬 저장)
4. git push (원격 올리기)
5. 다른 사람: git pull (받기)
💡 Pull을 먼저!
팀 프로젝트에서는 push 전에 항상 pull을 해서 최신 코드를 받으세요!

git push 원격에 올리기 git push
git pull 원격에서 가져오기 git pull
