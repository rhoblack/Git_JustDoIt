2장: 기본 작업 - 매일 사용하는 명령어

파일을 저장하고, 기록을 확인하고, GitHub에 올려봅시다!

🎯 이 장을 마치면 다음을 할 수 있습니다:

  • 파일을 Git에 등록(add)하고 변경사항을 저장(commit)할 수 있다
  • 스테이징 영역이 왜 필요한지 설명할 수 있다
  • 변경 기록(log)과 변경 내용(diff)을 확인할 수 있다
  • GitHub에 코드를 올리고(push) 받아올(pull) 수 있다
  • .gitignore로 불필요한 파일을 제외할 수 있다

💡왜 배우나요?

1장에서 Git 저장소를 만들었지만, 아직 아무것도 저장하지 않았습니다. 이 장에서 배우는 add → commit → push가 Git의 가장 기본이자, 매일 사용하는 핵심 워크플로우입니다.

이 세 가지만 익히면 Git의 80%를 활용하는 것과 같습니다!

📝2.1 파일 등록하기 (git add)

📌 용어: 스테이징 영역 (Staging Area)

한글 정의: 커밋(저장)하기 전에, "이번에 저장할 파일"을 골라 놓는 대기 공간입니다.

일상 비유: 택배를 보낼 때를 생각해보세요. 모든 물건을 한꺼번에 보내지 않고, 보낼 물건만 "포장 대기 테이블"에 올려놓죠? 스테이징 영역이 바로 그 테이블입니다.

왜 필요한가? 10개 파일을 수정했지만, 지금은 3개만 저장하고 싶을 때가 있습니다. 스테이징 영역이 있으면 원하는 파일만 골라서 저장할 수 있습니다.

파일의 상태 변화

[작업 폴더] → git add → [스테이징 영역] → git commit → [저장소]

파일 수정 → 포장 대기 테이블 → 택배 발송 완료

직접 해보기

1장에서 만든 my-first-project 폴더에서 계속 진행합니다.

Step 1: 파일 만들기
$ echo "Hello, Git!" > hello.txt

"Hello, Git!"이라는 내용의 파일이 만들어집니다. 이미 1장에서 만들었다면 이 단계는 건너뛰세요.

Step 2: 상태 확인하기
$ git status

📊 예상 결과:

Untracked files:
(use "git add <file>..." to include in what will be committed)
hello.txt

"Untracked"는 "Git이 아직 추적하지 않는 파일"입니다. Git에게 "이 파일을 관리해줘"라고 알려줘야 합니다.

Step 3: 파일을 스테이징 영역에 올리기
$ git add hello.txt

hello.txt를 "포장 대기 테이블"에 올렸습니다.

Step 4: 다시 상태 확인
$ git status

📊 예상 결과:

Changes to be committed:
(use "git rm --cached <file>..." to unstage)
new file: hello.txt

이제 "커밋될 변경사항"으로 표시됩니다. 저장할 준비가 된 것입니다!

✅ 성공!
파일을 스테이징 영역에 올렸습니다!

여러 파일 한 번에 추가하기

$ git add . # 현재 폴더의 모든 변경된 파일 추가
$ git add *.txt # .txt 파일만 모두 추가
$ git add folder/ # 특정 폴더의 모든 파일 추가
💡 실수로 add했다면?
스테이징을 취소하려면: git reset hello.txt
파일은 그대로 있고, 스테이징만 취소됩니다. 안전합니다!

💾2.2 변경사항 저장하기 (git commit)

📌 용어: 커밋 (Commit)

한글 정의: 스테이징된 파일들의 변경사항을 Git 저장소에 영구적으로 기록하는 행위입니다.

일상 비유: 포장 대기 테이블(스테이징)에 올려놓은 물건들을 "택배로 발송"하는 것입니다. 발송되면 언제 보냈는지, 뭘 보냈는지 기록이 남습니다.

왜 필요한가? 커밋이 있어야 "3일 전 상태로 되돌리기"가 가능합니다. 커밋 = 되돌릴 수 있는 저장 지점입니다.

직접 해보기

Step 1: 커밋하기
$ git commit -m "Add hello.txt file"

📊 예상 결과:

[master (root-commit) a1b2c3d] Add hello.txt file
1 file changed, 1 insertion(+)
create mode 100644 hello.txt

-m은 "message(메시지)"의 약자입니다. 큰따옴표 안에 "무엇을 했는지" 설명을 적습니다.

Step 2: 상태 확인
$ git status

📊 예상 결과:

nothing to commit, working tree clean

"더 이상 저장할 것이 없다"는 뜻입니다. 모든 변경사항이 안전하게 기록되었습니다!

Step 3: 한 번 더 수정하고 커밋해보기
$ echo "I am learning Git!" >> hello.txt

>>는 파일 끝에 내용을 추가합니다. (>는 덮어쓰기)

$ git add hello.txt
$ git commit -m "Add learning message to hello.txt"
✅ 성공!
두 번째 커밋까지 완료! 이제 2개의 저장 지점이 생겼습니다.
💡 좋은 커밋 메시지 작성법
✔ 좋은 예: "Add login feature", "Fix calculation bug", "Update README"
✘ 나쁜 예: "asdf", "수정", "update", "ㅋㅋ"
무엇을 했는지 명확하게 적으세요. 나중에 커밋 기록을 볼 때 큰 도움이 됩니다.
📌 add + commit 한 줄로 하기
이미 Git이 추적 중인 파일은 한 줄로 가능합니다:
git commit -am "메시지"
(-a는 수정된 추적 파일을 자동으로 add합니다. 새 파일에는 적용되지 않습니다.)

🔍2.3 기록 확인하기 (git log, git diff)

직접 해보기: 커밋 기록 보기

Step 1: 전체 커밋 기록 보기
$ git log

📊 예상 결과:

commit b2c3d4e5f6a7... (HEAD -> master)
Author: Kim Min-ho <kim@gmail.com>
Date: Mon Mar 15 10:30:00 2026

Add learning message to hello.txt

commit a1b2c3d4e5f6...
Author: Kim Min-ho <kim@gmail.com>
Date: Mon Mar 15 10:25:00 2026

Add hello.txt file

각 커밋에 누가(Author), 언제(Date), 무엇을(메시지) 했는지 기록되어 있습니다.

나가려면 q 키를 누르세요.

Step 2: 한 줄로 간단하게 보기
$ git log --oneline

📊 예상 결과:

b2c3d4e Add learning message to hello.txt
a1b2c3d Add hello.txt file

앞의 7자리(b2c3d4e)가 각 커밋의 고유 ID(해시값)입니다. 나중에 특정 커밋을 가리킬 때 사용합니다.

직접 해보기: 변경 내용 비교하기

Step 3: 파일 수정 후 변경 내용 확인
$ echo "Git is awesome!" >> hello.txt
$ git diff

📊 예상 결과:

diff --git a/hello.txt b/hello.txt
--- a/hello.txt
+++ b/hello.txt
@@ -1,2 +1,3 @@
Hello, Git!
I am learning Git!
+Git is awesome!

+로 시작하는 줄은 추가된 내용, -로 시작하는 줄은 삭제된 내용입니다.

Step 4: 변경사항 저장하기
$ git add hello.txt
$ git commit -m "Add awesome message"
✅ 성공!
세 번째 커밋까지 완료! 커밋 기록과 변경 내용을 확인하는 방법을 배웠습니다.

🔄2.4 GitHub에 올리고 받아오기 (push & pull)

📌 용어: Origin (원격 저장소 이름)

한글 정의: 원격 저장소(GitHub)의 기본 이름입니다. "origin"은 "원본"이라는 뜻입니다.

일상 비유: 내 컴퓨터의 파일을 Google Drive에 백업할 때, Google Drive를 "origin"이라고 부르는 것과 같습니다.

왜 필요한가? 컴퓨터가 고장나도 GitHub에 백업이 있으면 안전합니다. 또한 다른 사람과 코드를 공유할 수 있습니다.

직접 해보기: GitHub에 올리기

Step 1: GitHub에서 원격 저장소 만들기
  1. GitHub.com에 로그인합니다
  2. 오른쪽 상단의 "+" 버튼 → "New repository" 클릭
  3. Repository name에 "my-first-project" 입력
  4. "Create repository" 클릭
Step 2: 로컬 저장소와 GitHub 연결하기
$ git remote add origin https://github.com/사용자이름/my-first-project.git

GitHub에서 제공하는 URL을 사용합니다. 연결을 확인하려면:

$ git remote -v

📊 예상 결과:

origin https://github.com/사용자이름/my-first-project.git (fetch)
origin https://github.com/사용자이름/my-first-project.git (push)
Step 3: GitHub에 올리기 (Push)
$ git push -u origin master

📊 예상 결과:

Enumerating objects: 9, done.
Counting objects: 100% (9/9), done.
...
To https://github.com/사용자이름/my-first-project.git
* [new branch] master -> master
Branch 'master' set up to track remote branch 'master' from 'origin'.

-u는 처음 한 번만 필요합니다. 이후에는 git push만 입력하면 됩니다.

✅ 성공!
GitHub에서 내 코드를 확인해보세요! 브라우저에서 저장소 페이지를 새로고침하면 파일이 나타납니다.

Push 실패 시 해결 방법

에러: "rejected - non-fast-forward"
! [rejected] master -> master (non-fast-forward)
error: failed to push some refs to '...'

원인: 다른 사람(또는 GitHub에서 직접)이 변경사항을 올렸는데, 내가 받지 않고 push하려고 할 때 발생합니다.

해결:

$ git pull origin master # 먼저 받아오기
$ git push origin master # 다시 올리기
에러: "Authentication failed"

원인: GitHub 인증 정보가 잘못되었을 때 발생합니다.

해결: GitHub에서 Personal Access Token을 생성하고, 비밀번호 대신 토큰을 사용하세요. (GitHub → Settings → Developer settings → Personal access tokens)

직접 해보기: GitHub에서 받아오기 (Pull)

Step 4: 원격 저장소에서 가져오기
$ git pull origin master

다른 사람이 올린 변경사항이나 GitHub에서 직접 수정한 내용을 내 컴퓨터로 가져옵니다.

이후에는 git pull만 입력해도 됩니다.

Git 기본 워크플로우 (매일 반복!)

1. 파일 수정
2. git add (스테이징)
3. git commit -m "메시지" (로컬 저장)
4. git push (GitHub에 올리기)

팀원이 올린 코드 받기: git pull
💡 Pull을 먼저!
팀 프로젝트에서는 작업 시작 전에 항상 git pull을 해서 최신 코드를 받으세요. 이렇게 하면 충돌을 줄일 수 있습니다.

🚫2.5 불필요한 파일 제외하기 (.gitignore)

📌 용어: .gitignore

한글 정의: Git이 무시해야 할 파일 목록을 적어놓는 파일입니다.

일상 비유: 택배를 보낼 때 "이건 안 보내도 돼" 목록을 만드는 것과 같습니다. 비밀번호 파일, 임시 파일 등은 Git에 올리면 안 되니까요.

왜 필요한가? 비밀번호, API 키 같은 민감한 정보가 GitHub에 올라가면 보안 사고가 발생합니다. 또한 컴파일 결과물 같은 임시 파일은 올릴 필요가 없습니다.

직접 해보기

Step 1: .gitignore 파일 만들기
$ echo "secret.txt" > .gitignore
Step 2: 무시되는지 확인하기
$ echo "my-password-123" > secret.txt
$ git status

📊 예상 결과:

Untracked files:
.gitignore

secret.txt가 목록에 나타나지 않습니다! Git이 무시하고 있습니다.

Step 3: .gitignore 파일 커밋하기
$ git add .gitignore
$ git commit -m "Add .gitignore file"
✅ 성공!
이제 secret.txt는 Git이 추적하지 않습니다!

자주 사용하는 .gitignore 패턴

# 비밀 파일
.env
*.key
config/secrets.yml

# 운영체제 파일
.DS_Store
Thumbs.db

# 임시 파일
*.log
*.tmp

# 빌드 결과물
node_modules/
__pycache__/
*.class
💡 프로젝트 시작할 때 .gitignore를 먼저 만드세요!
나중에 추가하면, 이미 Git에 올라간 파일은 별도 작업이 필요합니다. 처음부터 설정하는 것이 훨씬 쉽습니다.

📚2장 핵심 요약

명령어 역할 사용 장면
git add 파일명 파일을 스테이징 커밋 전 저장할 파일 선택
git add . 모든 변경 파일 스테이징 전부 다 저장하고 싶을 때
git commit -m "메시지" 변경사항 저장 작업 완료 후 기록
git log --oneline 커밋 기록 보기 이전 작업 확인
git diff 변경 내용 비교 뭐가 바뀌었는지 확인
git push GitHub에 올리기 백업 및 공유
git pull GitHub에서 받기 팀원 변경사항 받기
.gitignore 파일 무시 목록 비밀 파일, 임시 파일 제외
