## ✅ 긍정적인 평가

- **브랜치 개념**: "독립적인 작업 공간"이라는 설명으로 이해됨
- **git branch, checkout**: 명령어가 명확하고 따라하기 쉬움
- **Merge 설명**: "코드를 합치는 것"이라는 비유 좋음
- **충돌 마커**: <<<, ===, >>>가 명확하게 보임
- **Pull Request**: GitHub에서 실제로 보이는 화면 설명 매우 도움
- **협업의 의미**: 팀원과 함께 작업하는 것의 중요성을 느낌

---

## 💭 처음엔 어려웠지만 이해된 부분

- **충돌이 왜 생기는가**: "같은 파일의 같은 줄을 바꾸면 Git이 뭘 선택할지 몰라서" → 아!
- **충돌 해결 방법**: 처음엔 "뭘 지우고 뭘 남길지?"라는 생각했는데, "둘 다 검토해서 옳은 것 선택"이라고 하니 이해됨
- **Pull Request**: "왜 merge를 또 하는 거지?"라고 생각했는데, "팀원이 확인 후 승인"하는 과정이라고 하니 의미 있음

---

## ⚠️ 약간 어려운 부분

- **충돌 마커**: 기호 (<<<, ===, >>>)가 여러 개면 헷갈릴 수 있을 것 같음
- **여러 명이 같은 파일 수정**: 언제 충돌이 생기고 언제 안 생기는지 완벽히 이해 안 됨 (하지만 실습하면서 배울 것 같음)

---

## 🎯 실습 가능성

**가능도**: 95% ✅

- git branch feature/new (브랜치 생성) - 쉬움
- git checkout feature/new (전환) - 쉬움
- 파일 수정 후 commit - 2장에서 배웠으니 쉬움
- git merge feature/new (병합) - 쉬움
- 충돌 해결 - 약간 복잡하지만 설명 따라가면 가능

**어려울 수 있는 부분**:
- 의도적으로 충돌을 만들어야 실습 가능
- 하지만 설명이 있어서 따라갈 수 있음
