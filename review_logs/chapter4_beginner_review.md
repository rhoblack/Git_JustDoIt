## ✅ 긍정적인 평가

- **Revert 개념**: "되돌리는 커밋을 만드는 것"이라고 하니 안전하게 느껴짐
- **Reset의 3가지**: soft, mixed, hard를 구분해서 설명해주니 이해됨
- **Stash**: "임시 보관함"이라는 비유가 와닿음
- **실전 상황**: "커밋을 잘못 쓴 경우"처럼 실제 경험 다룸
- **위험성 경고**: "git reset --hard는 조심하세요"라고 친절히 경고
- **복구 방법**: reflog로 되돌릴 수 있다는 설명이 마음 편함

---

## 💭 처음엔 어려웠지만 이해된 부분

- **Revert와 Reset의 차이**: "Revert는 새로운 커밋을 만들고, Reset은 커밋 자체를 없앤다"고 해서 이해됨
- **Reset의 soft, mixed, hard**: 처음엔 뭔 말인지 몰랐는데, "커밋만 취소 vs 파일도 취소 vs 전부 취소"라고 하니 명확함
- **왜 Revert를 쓸까**: "공개된 브랜치에서는 safe하기 때문"이라고 하니 의미 있음

---

## ⚠️ 여전히 어려운 부분

- **Reflog**: "git reflog"가 뭔지는 알았는데, 실제로 언제 써야 할지는 아직 안 함 (고급 개념인 것 같음)
- **Reset 연습**: soft, mixed, hard 모두를 실습하기 어려울 것 같음 (실수가 두렵긴 함)
- **Rebase**: 이것도 개념은 알겠는데, 실제로 쓸 일이 있을지는 모르겠음

---

## 🎯 실습 가능성

**가능도**: 80% ✅

- git revert HEAD - 쉬움 (안전함)
- git reset HEAD~ --soft - 약간 복잡
- git stash / stash pop - 매우 쉬움
- git reflog - 복잡함 (아직 실습 안 함)
- git rebase - 복잡함 (아직 시도 안 함)

**어려울 수 있는 부분**:
- Reflog, Rebase는 고급 내용
- Reset은 실수가 두려움
- 하지만 설명이 충분해서 나중에 필요할 때 다시 읽으면 될 것 같음
